# AgentMemory

Everything the working agent knows and understands about this
project, externalized. A forked or fresh conversation is briefed by
reading THIS FOLDER plus the owner's communication protocol (in the owner's
preferences) — zero conversation scrollback required.

## Read before any of it

`PseudoCoupHQ/plan_and_code.md` (the owner, 2026-07-31). Plan
names ARE code names; code is written top-down with logic last; every
node carries a `designation`. Neither this project's plan nor its
code conforms yet — bringing them into conformance is the next job,
and this folder does not yet describe the conforming state.

## Load order

1. `00_project.md` — what this is, goals, components, foundation.
2. `01_vocabulary.md` — settled terms. Check before using any term.
3. `02_decisions.md` — settled decisions with reasons and who made
   them. New reasoning must be checked against this file BEFORE
   being asserted (see lesson L-name in 04).
4. `03_lineage_and_harvest.md` — the version map and where the
   best components live.
5. `04_lessons.md` — measured project lessons AND the agent's own
   recorded failure modes with their guards.
6. `05_state.md` — current state, open questions, immediate next
   actions. The most volatile file.

## Maintenance rules

- Update AT THE MOMENT a decision or correction happens — never
  chat-only. A fact that exists only in conversation is considered
  lost.
- Corrections preserve the fallen position and WHY it fell
  (project standing rule).
- This folder is understanding; `DevComms/` is workflow (session
  state updates, commit messages, handoffs, working logs). A fact
  needed to work correctly belongs here; a record of what happened
  belongs in DevComms.
- Keep files tight. Depth lives in the referenced documents; this
  folder holds what must be loaded every time.
