# 1. What the objects are

- **a component** — one c-bearing pool entry of `the_pool5.json`, in
  the target's machine-type-key bucket, rebuilt as a z3 function of
  its inputs by `term_to_lean.py`'s parser (`Parser` + `infer` +
  `roundtrip` + `to_z3`; stated once, `synthesis_plan.json`'s
  `"parser"` field, LITERAL below).
- **a target** — an x entry (go, rust or swift member, no c member;
  task o7's population P3, 206 entries) with its own term S, the thing
  a composition must equal.
- **a composition** — a tree of components, the target's inputs at the
  leaves, found by CEGIS: guess a tree consistent with the
  counterexamples so far, ask z3 (at the gate's 3,000 ms) for an input
  where the guess disagrees with S; unsat proves it, sat adds the
  input and repeats, for program length k = 1, 2, 3.
- **the oracle** — for every target where BOTH this route and task
  o7's compiled-emulation route answered: do they land on the same
  pool entry, are both PROVED, and does the compiler route's own term
  land in a pool entry that is also a component of this route's
  composition.

    """a producing component's answer may enter any consuming
