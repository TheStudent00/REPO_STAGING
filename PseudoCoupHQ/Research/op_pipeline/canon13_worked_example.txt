THE FIX, in one line: canon13_render.py's `gen_bool()` recognizes an
`and`/`or`/`not` z3 Bool node and folds its operands with real `and`/
`or`/`xor $1` on canonical 0/1 bytes (sound because bitwise and/or of
two 0/1-valued bytes IS logical and/or); the `if` node's dispatch now
checks its own condition's decl name BEFORE calling
decode_bool_condition and routes to gen_bool on `and`/`or` instead of
raising.

A SECOND, necessary fix surfaced getting this far, undone in the
process (the owner's evidence doctrine -- report wrong turns caught, not
just the final answer): gen11/gen12's own internal recursion (concat
fold, shift, extract, the general ALU fold) called the literal name
`gen11`/`gen12`, not the module's own late-bound `gen7` -- so a
compound-and/or `If` node BURIED inside an outer Concat (exactly
c/op_551's own shape) never reached gen13's new rule at all; codegen
raised Unsupported one recursion level short of gen13's own dispatch,
even after gen13 existed. Diagnosed by direct trace (c/op_551 kept
refusing after gen13 was written and imported correctly). THE FIX:
every recursive call site inside canon11_render.gen11 (15 call sites)
and canon12_render._gen_wide_divmod (2 call sites) now reads
`R7.gen7(child, ...)` instead of the literal function name -- the
SAME late-binding trick canon7_render._gen_alu already used, applied
one level deeper, so a node nested inside ANY earlier stage's own
traversal still reaches whichever stage is currently topmost.
