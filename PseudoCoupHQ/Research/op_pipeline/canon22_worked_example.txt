WHY THIS UNIT WAS STUCK BEFORE THIS LAP: condition_table4.py's own
substitution already turned the `amd64g_calculate_condition` call
into an `FCUGT(CmpF64(P,Q))` atom (P = a converted to f32 then widened
to f64 for VEX's own CmpF64 helper, Q = b, native f32 widened the
same way) -- but canon17_float.classify_float_operand's own six-shape
whitelist only recognizes P/Q as a NATIVE float register or the
literal zero; a's own converted value (`F32toF64(F64toF32(<rm>,
I32StoF64(ex32@0(in0:64))))`) matched none of the six, so canon17_
render.py refused honestly (`Unsupported`), which downstream reporting
recorded as the generic "amd64g_calculate_condition... condition-code
helper call" refusal the task's own brief quoted verbatim.
condition_table8.classify_float_operand8 recognizes this exact shape
(condition_table6.classify_conv_expr's own i32_to_f32 kind, unwrapped
from VEX's own outer ucomiss-compare widen), records the REAL compare
width (32, ucomiss, not the widened 64), and canon22_render.py emits
the real `cvtsi2ss` instruction real ship code itself uses.

GATE (canon22_behaviour_check.anchored_check, real z3 FPA --
fpSignedToFP for the conversion, fpLT/fpEQ/fpIsNaN for the ucomiss
