## definition

`operator_for : dict[(SailPrimitive, widths) -> list[ArchUnit]]`

The swap table, the owner's `lang_x_arch_unit_lean_primitives`: for each Sail
primitive at given operand widths, the units of `compiler_corpus` whose
meaning is that primitive applied to unknowns.

- filled only by `System.pass_a_find` step 2:
  `LeanExpr.equals(primitive(x, y), unit.lean)` proved in Lean. An entry
  that is not a proof does not exist.
- several units may prove equal (c's `+` on `int64_t` and on `uint64_t`
  both mean `BitVec.add` at 64): all are kept, in corpus order; `render`
  uses the first.
- an absent key is what sends `render` to `compose_at_width`; it is
  never filled by a guess, a table, or a spelling.
- if we take every proved (primitive, unit) pair of a language and group
  the units by their primitive and widths, that is operator_for.

The file: `operator_for.json` per language in the run's directory, with
the proof file of each entry named beside it; regenerated by every run,
never edited. The keys are Sail's own names of the primitives
(`BitVec.add`, `Int.tdiv`, `shift_bits_left`, ...) with widths, so the
spelling-ban checker passes: no operator token, no mnemonic, is a key.
