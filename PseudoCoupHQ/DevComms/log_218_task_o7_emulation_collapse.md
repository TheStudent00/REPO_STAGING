# 1. What the objects are

- **an arch-unit** — one compiled function body, carved out of a
  shipped object file with the pipeline's own objdump reader
  (`lane_gen.extract`).
- **a pool entry** — the set of arch-units, across languages, that
  were proved to answer the same for every input
  (`PRIVATE/PseudoCoupHQ/Research/op_pipeline/the_pool5.json`).
- **a term** — one arch-unit written as a z3 expression; the entry's
  **layer-5 text** is that expression printed by one fixed rule.
- **an x unit** — a member of a pool entry in go, rust or swift whose
  entry has NO c member: nobody has built the c arch-unit that answers
  the same. Task o1's length-one map
  (`PRIVATE/PseudoCoupHQ/Research/oracle/cross_construction/cross1_length_one.json`)
  names them.
- **an emulation** — a c function whose body is that entry's term
  written in c's own operations over c's holders, produced by the ONE
  renderer in `emulate.py` (`Renderer`) from the z3 term. A term the
  renderer cannot render is refused by cause and no source is written.
- **the collapse test** — compile the emulation at the flags the whole
  c corpus was built with, carve the body, and ask three questions,
  each answered separately: Q1 are its bytes bytes some c unit already
  has; Q2 is its printed term the entry's text; Q3 does the solver
  prove it answers as the x unit does for every input.

# 2. What was done and what came back

the owner asked whether a deliberately complicated program that computes
what some other language's unit computes gets lowered back into that
unit. This task asked exactly that of one compiler, over the pool.

For every entry that has an x member and no c member, the renderer
wrote the entry's term out as c — the term's shape kept exactly, so
the source is long, nested, and nothing a person would write — and
clang compiled it at `-std=c17 -O1`, the ship build of the c corpus.
The compiled body was carved with the reader the corpus uses, put on
the canonical form, and its own term rebuilt, so the three questions
could be asked of a real arch-unit rather than of source text.

At the byte level the answer is mostly no: 5 of the 204 compiled
emulations came out carrying bytes an existing c unit already has. At
the level of behaviour the answer is mostly yes: 168 of 204 were
proved equal to the x unit, and 25 more once every byte-wide or
halfword-wide argument is taken to arrive already widened to the
register — which is what c's callee assumes — for 193 of 204.

The control is what makes those two numbers readable. Take 40 entries
that DO have a c member, render the emulation from that member's own
term, and ask whether clang lands back on that member's own bytes: it
does so 14 times in 33. So byte identity was never going to be the
measure — clang has more than one way to spell the same answer, and
the renderer's long nested source does not always reduce to the
spelling the original unit was given, even when that unit is c's own.

Where the proof failed and the arrival-width re-posing did not rescue
it — 11 emulations — the x unit's own body carries a conditional
branch the term does not carry, in 6 of them: the body tests an input
and returns down another path (a zero divisor, a signed extreme),
while the term is total and has no such case. The other 5 are listed
with their seeds in section 8 and are NOT attributed to a cause by
this task.

Two sample lanes were run before the run of record and both are in
the lane logs: `o7_l2` refused every rust entry with "rebuilt term
prints differently from the pool's text", because today's
`Term.normalize` and the pool's stored text can differ in the ORDER of
a commutative operation's arguments. `emulate.py` gained a check that
compares the two through task o1's parser under that order (`same up
to commutative order and variable index`), and `o7_l5` is the sample
of record.
