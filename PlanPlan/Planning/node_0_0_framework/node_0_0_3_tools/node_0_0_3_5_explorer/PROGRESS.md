# PROGRESS — explorer

- 2026-08-05: node folder generated by
  `PRIVATE/PlanPlan/framework/generate_nodes.py` from the
  `nodes` register of `PRIVATE/PlanPlan/Planning/node_0_0_framework/node_0_0_3_tools/CORE_0_0_3_tools.md`. Skeleton only — definition,
  designation, and content pending.
- 2026-08-05 **done and exercised**: the tool exists, both modes work.
  - Snapshot mode on PCv5: 23 cards in the payload, 21 KB, one inline
    `<script>`, no `src=` and no external reference of any kind.
  - Serve mode verified to genuinely re-scan: with the server running
    on HQ's tree, a node folder was created and the next request
    reported 5 nodes where the previous reported 4 — no restart, no
    cache.
  - `realize: false` entries render as marked cards, so `ur`'s `tree`
    and `kinds`, and `builder`'s six attributes and methods, appear —
    structure that `render_plan`'s HTML view omits entirely.
- 2026-08-05 **corrected the same day**, on two counts the owner named:
  - **It takes several roots now, and the whole line is the default
    view.** "the explorer is for the entire project" — a view showing
    one repo at a time makes the reader hold the other three in their
    head, which is the job the view was supposed to do. With more than
    one root it synthesizes a top card, and each repo card is named
    for the repo, not the root's id, because the repo name is what a
    reader navigates by on disk.
  - **No flag and no path to type.** `hq.sh explore` writes
    `PRIVATE/PseudoCoupHQ/plan_explorer.html` and prints where it
    went. The earlier form demanded `-o` and an invented Desktop path.
    A default output that a caller must supply is not a default.
  - The file is gitignored: generated, regenerate rather than commit.
    It cannot live inside a planning tree — an `.html` in a node
    folder is a stray by the grammar.
  - `serve` was dropped from `hq.sh`. It exists only for the
    auto-update case, and the owner does not want a server: "i just want a
    script to generate the explorer data and then an html i can open."
    It remains available through `plan.sh serve` for the day that
    question comes back.
  - Measured after: 56 cards over four trees, 57 KB, one inline
    script, nothing fetched.

- 2026-08-05 **open**: the cross-tree edges — six, between HQ and the
  three project roots — are in the frontmatter and still have no view.
  The explorer now shows all four trees on one page, but as siblings:
  it does not draw the edges BETWEEN them. That was the highest-value
  next diagram in the display proposal, and it is not built.
