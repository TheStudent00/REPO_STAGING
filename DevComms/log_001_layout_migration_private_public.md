## 1. Plain words: what is happening and why it matters to you

Every repo that is a working clone of one of the owner's GitHub repos moves
one level down, into `PRIVATE/<name>` or
`PUBLIC/<name>`, matching its GitHub visibility. A
symlink stays at the old name, so every existing path in every file
keeps resolving. Nothing in git changes: same remotes, same branches,
same history. Your work is not interrupted, and your existing
references are not wrong, but new references you write after the move
must use the new real path.

## 2. Words used below, declared before use

`class`
- PRIVATE or PUBLIC, as GitHub reports it for a repo.
- built: `gh repo list <owner> --json name,visibility`.

`working clone`
- a folder directly under `~/Programming` (or directly under the
  grouping folder `WFL_Projects`) that has a `.git` whose
  origin is `github.com/<owner>/<name>`. Only these move.

`real path`
- where the repo's files physically are after the move:
  `PRIVATE/PseudoCoupHQ`.

`compatibility link`
- the symlink left at the old name, pointing at the real path:
  `PRIVATE/PseudoCoupHQ -> PRIVATE/PseudoCoupHQ`. It exists so
  that unrewritten references keep working. It is not the address to
  write into new work.

`reference`
- a literal path string in any file that names a repo by its old
  location: `PRIVATE/PseudoCoupHQ`, `$HOME/Programming/PRIVATE/Misc`,
  `PUBLIC/Airlock`.

`Phase 5`
- the later, per-repo rewrite of every reference from old location to
  real path, landed as one commit per repo, after which that repo's
  compatibility link can be retired. Not started until the owner says so.

## 4. How to tell which state the disk is in (run this, do not guess)

```
# one command; its output is the state
if   [ -L PRIVATE/PseudoCoupHQ ]; then echo "MOVED: real path is $(readlink -f PRIVATE/PseudoCoupHQ)"
elif [ -d PRIVATE/PseudoCoupHQ ]; then echo "MOVED, LINK RETIRED: use PRIVATE/PseudoCoupHQ"
else echo "NOT MOVED: old paths are the real paths"
fi
```

`readlink -f <any old path>` always gives the real path, in every state.

## 5. What you must do, by state

```
STATE = NOT MOVED
  change nothing. keep writing paths as you do today.
  commit and push your work as usual (the daemon does it within 30 s).
  do NOT pre-emptively write PRIVATE/ or PUBLIC/ paths; they do not exist yet.

STATE = MOVED  (compatibility links present)
  existing references in files:   leave them. they resolve through the links.
                                   do NOT rewrite them in bulk; that is Phase 5, one commit per repo, on the owner's word.
  NEW references you write:        use the real path from the table in §3.
                                   PRIVATE/PseudoCoupHQ, not PRIVATE/PseudoCoupHQ.
  your working directory:          either path works. prefer the real path when you start a session.
  Airlock instances and lanes:     no change. container paths are unchanged (§3, last paragraph).
  LAW.md and briefs:               their paths still resolve. a brief you WRITE after the move uses real paths.
  new repos:                        created directly at PRIVATE/<name> (new repos are private).
                                   never at the top level, never in PUBLIC/ without the owner's word.

STATE = MOVED, LINK RETIRED  (Phase 5 done for that repo)
  every reference to that repo uses its real path. an old path that no longer resolves is a defect: fix it
  by the rule in §6, in the repo you are working in, as part of your normal commit.
```

## 10. The drift check, live since 2026-09-10 15:51

`PRIVATE/Misc/repo_daemon/repo_daemon.py`, function
`class_drift`, runs on every repo on every tick. The folder class
(PRIVATE or PUBLIC, the first path component under `~/Programming`) is
compared with GitHub's answer (`repo_visibility`, cached a day; an
answer GitHub could not give is treated as unknown, never as a
verdict). Three outcomes:

```
no class folder in the path, or folder == GitHub, or GitHub unknown  ->  nothing
folder != GitHub, repo is the class folder's own child                ->  log "CLASS DRIFT", HOLD (no commit, no push), shown in `repo-daemon status`
folder != GitHub, repo is nested inside another repo's tree           ->  log "CLASS DRIFT ... (nested clone; reported, not held)"
```

On its first pass it found two nested straddlers, both pre-existing and
both reported, not held:

- `PRIVATE/StressBot/RelevantProjects/PseudoCoup_v0` —
  its origin is the PUBLIC repo `PseudoCoup`, inside the PRIVATE
  StressBot tree.
- `PUBLIC/Ourobrowser/Tools/PCv3.1/PseudoCoup_v2` — a
  PRIVATE repo's clone inside the PUBLIC Ourobrowser tree (see §11 for
  whether Ourobrowser's git can see it).

All seventeen direct working copies agree with GitHub.

## 13. Retiring the links, 2026-09-10 (the owner's decision)

The old names are SYMLINKS, not copies: one set of files, one inode,
so nothing can drift between an old name and its real path. the owner wants
the old names gone anyway so that any attempt to use one fails loudly.
The script `PRIVATE/Misc/layout_migration/retire_links.sh`
removes the eighteen links (symlinks only; it aborts before any `rm` if
a path is not a symlink into PRIVATE/ or PUBLIC/). Once it has run:

```
STATE = MOVED, LINKS RETIRED  (all repos at once)
  <oldname>            -> does not exist. A script or a cd that uses it FAILS. That is intended.
  the real path is the only path:    PRIVATE/<name> or PUBLIC/<name> (table in §3)
  fix a failing old path by the §6 rule, in the repo you are in, in your normal commit.
```

What is known to start failing on the laptop the moment the links go:

- `hq.sh check` (and so `hq.sh` in commit mode, which pushes nothing
  on an error) reports every documentation reference to an old path as
  `dangling-path`: about 1,030 markdown files across the repos (485 in
  PseudoCoupHQ alone). That list IS the Phase 5 worklist. Until Phase
  5 lands per repo, planning pushes go through the daemon, not hq.sh.
- Per-repo `git_commit_push.sh` and `create_github_repo.sh` scripts
  (already superseded by the daemon; several were stale before today).
- Env-overridable defaults in PseudoIR/Tools and PseudoCoup_v5/Research
  scripts (`PSEUDOCOUP_ROOT`, `PC_SOURCES`) when run without the
  variable set.

What does NOT fail, and must not be "fixed" by the §6 rule:

- Lane scripts and their recorded outputs under
  `PRIVATE/PseudoCoupHQ/Research/**` (379 files) name
  `PRIVATE/PseudoCoupHQ/...` because they run on the TOWER, whose
  `~/Programming` is flat; `PUBLIC/Airlock/remote_lane.sh`
  maps PRIVATE/ and PUBLIC/ to that flat layout on sync. A lane script
  is rewritten only if it runs on the laptop host. Inside the laptop's
  Airlock container the paths are `<name>`, unchanged.

Retargeted before retiring: the tracked link
`PRIVATE/WFL_PseudoCoup/.DevComms/LLM_communication_protocol.md`
now points at `../../DevComms/...` (PRIVATE/DevComms directly) instead
of `../../../DevComms/...`, which went through the old name.
