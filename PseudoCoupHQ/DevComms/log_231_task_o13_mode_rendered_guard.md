# 1. What the objects are

- **the guard** — in a unit's ledger, the GUARD-block rows whose
  producer pair is a flag setter and a conditional-branch reader (e.g.
  `test`/`je`), read off `record["ledger"]` by `mode.py`'s
  `branch_guard_rows()`; each row names the block(s) its flag operands
  came from, giving a vocabulary key like `test je on IN IN`. The
  branch these rows gate reaches a departing path whose OUTCOME —
  trap, or a call to a routine that never returns — is read off the
  path itself, never assumed.
- **the mode** — one x unit's set of guard rows, rendered before the
  operation as an `if` in the emulation's own source: the condition
  from the ledger's rows, the outcome from the departing path's own
  outcome kind. `mode.py`'s `ModeRendererC` (c) and its rust
  counterpart do this by reading the reference walk, never by a
  hand-written guard.
- **the re-run** — the 36 c and 59 rust emulations task o7 (log 218)
  and task o11 (log 226) recorded DISPROVED, rendered with the mode,
  recompiled, carved, and gated against the x unit again at the gate's
  3,000 ms (the verdict of record); a second pass at a raised solver
  ceiling (30,000 ms) checks whether the 3,000 ms verdict is itself a
  ceiling artifact.
- **the diagnose** — for an emulation the mode still does not prove,
  the two guarded answers and the two guard conditions, evaluated at
  the solver's own counterexample model, with the caller-extension
  rule applied where the unit's own parameters are narrower than 32
  bits.
