# PROGRESS — checks

- 2026-08-02 **done and exercised**: `EdgeRegisterCheck` and
  `CheckFrontmatterCheck` added, and the CONFORMANCE GAPS banner
  extended to cover both.
  - **What the edge check can see that nothing could before**: a node
    attached somewhere other than where it says. Both halves of such
    an edge resolve on disk, so the dangling-path check is silent on
    it; only comparing the two ends reveals it.
  - Severities follow the `designation` precedent. A field ABSENT is a
    WARN, because every tree predates the fields and erroring would
    refuse every commit until 52 nodes were rewritten at once — the
    sweep §6c warns against. A field MALFORMED is an ERROR, because
    that is not a node waiting to conform but a node claiming
    something unreadable.
  - The far end of an edge is read straight from disk whether or not
    its tree was passed on the command line. A cross-tree edge usually
    points into a tree nobody named, and refusing to look would leave
    exactly the edge these fields exist for unchecked.
  - **Exercised on a synthetic pair of trees**, one healthy and one
    carrying a different defect per node. The healthy tree produced no
    edge finding at all — the negative control. The other produced one
    of each, all four categories: `edge-malformed` (a `super_node`
    with a `description` and no `path`), `edge-unresolved` (a
    `sub_nodes` entry naming a folder that does not exist),
    `edge-one-ended` (three shapes — an absent `super_node`, a
    malformed one, and a node hanging under a node that does not name
    it back), and `edge-disagreement` (a node whose `super_node`
    points at one of its own co-nodes while the root names it as a
    sub-node).
  - `CheckFrontmatterCheck` exercised the same way: a CHECK carrying
    `id: b.broken.WRONG.check` under a node whose id is `b.broken` was
    reported as an ERROR naming both the id found and the id expected.
    A CHECK with no frontmatter at all counts toward the WARN instead.
  - Measured on the real trees after the change: 0 errors, and the
    banner now names 52 of 52 nodes as missing the edge fields and 52
    of 52 CHECK files as missing their id. Both are expected — no
    chain has been brought to the new rules yet.
